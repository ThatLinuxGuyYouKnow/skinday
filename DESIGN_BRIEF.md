# SkinDay — Designer Brief

## What it is
**SkinDay** — *"Dress for the skin you're in today."* A mobile-first web app where
one selfie produces a live skin-state reading, which then drives head-to-toe look
recommendations (makeup + outfit) as a one-click bundle checkout. Core thesis:
**skin tone is static, skin state is daily** — redness, oil, dryness, and texture
today should change what fashion the app recommends, not just what foundation shade.

Track: YouCam hackathon, Skin AI + eCommerce VTO fusion. Consumer value: fewer
returns via refusal-first advice. Retail value: higher bundle AOV.

## User & moment
A shopper getting ready for a specific occasion (Interview / Date Night / Diwali
Dinner / Travel). They want to look right *today*, not in general. They distrust
generic shade finders and "complete the look" carousels with no reasoning.

## Core loop (60 seconds, single page, no nav)
1. **Scan** — upload one selfie (this session only, explicit consent framing).
2. **Occasion** — pick one of four chips; the recommendation logic adapts to it.
3. **Get today's look** — one CTA returns everything below.
4. **Read results** — skin-state card → why-math card → makeup render → outfit render.
5. **Bundle checkout** — add garments + makeup items to a persistent cart.

## Screen inventory (one scrolling page, in order)
1. **Brand header** — "SkinDay." serif wordmark with berry dot, one-line tagline,
   unit-meter pill ("demo mode · 0 spent").
2. **Step 1 card** — file input + uploaded photo preview.
3. **Step 2 card** — four occasion chips, single-select.
4. **CTA** — full-width berry button ("Get today's look"), loading state
   ("Reading skin…").
5. **Mode line** — "Precomputed demo" badge + mode/occasion metadata.
6. **Skin-state card** — skin-tone swatch dot + hex + undertone; strongest-signal
   summary; 7 ranked concern bars (Blemishes, Redness, Oil/shine, Dryness shown
   inverted, Texture, Dullness, Under-eye shadow), color-coded high/moderate/calm.
7. **Why card** — "Skipped for today" rows (✕ + item + reason, e.g. *"True-red
   matte lip — high-chroma red competes with redness"*), "Picked instead" rows
   (✓), palette rows with garment swatch + ΔE contrast chip + note (e.g. Forest
   top ΔE 46.8 "won't wash you out" vs nude camel ΔE 11.1 "refused, washes out").
8. **Makeup render** — before/after overlay slider with divider + grip handle,
   drag anywhere.
9. **Outfit render** — full-bleed VTO image + caption.
10. **Bundle checkout card** — 4 rows (2 garments incl. one flagged
    refused-but-visible, 2 makeup items), Add/Added toggle buttons, cart count
    line, Clear link.
11. **Honesty footnote** — cosmetic-preview-only, no medical/fit claims,
    session-only photo, stock-portrait disclosure.

## Real data shaping the design (golden run)
- Skin `#b0896c`, warm undertone; redness 94.3, oil 73, dryness signal high,
  skin age 63.
- 4 refusals / 5 prefers generated by a deterministic rule engine from raw scores.
- Palette math is real ΔE\*ab contrast numbers the UI must always show beside
  claims — **no recommendation without its number** is a product rule.
- Every claim traces to a score; copy is cosmetic-only, never medical ("reads
  stronger," "flatters," never "treats/heals").

## Current visual direction (built, open to redo)
Warm beauty-editorial: cream `#faf6f1` bg, white cards, ink `#1c1917` text, berry
`#8e2f45` primary (from the lip shade), forest `#1f4d3a` success, amber `#c2703d`
moderate. Serif (Georgia) wordmark + headings, system sans body. 720px max
column, 16px radius cards, pill chips, dashed honesty footnote. Reference tokens
live in `app/globals.css`.

## Component/motion notes
- Compare slider: overlay clip-path, divider + circular grip, full-image
  invisible range input for drag.
- Bars animate width on reveal (not yet built — nice motion task).
- Staggered tile reveal during the ~20s live cloth render, with honest loading
  copy (don't fake instant results).
- Face-lock toggle and look-A-vs-look-B are in scope docs but **not built** —
  greenfield for the designer.
- No raw JSON anywhere on screen; numbers only appear as explained scores
  (bars, ΔE chips).

## Constraints (non-negotiable)
- Mobile-first, single page, must survive as static + fixture fallback: if the
  API is down or out of units, the page shows the labeled precomputed run —
  never a dead app or error wall.
- WCAG-reasonable contrast, visible focus states, all imagery captioned "visual
  preview only, not a fit guarantee."
- No third-party marks/music in demo assets; fixture faces are stock portraits
  and must stay labeled as such.
- Must work with zero backend: localStorage cart only, no auth, no DB.

## Assets available
- `public/fixtures/`: golden makeup + outfit renders, 8 skin-concern mask
  overlays (redness, oil, moisture, etc. — usable as heatmap overlays), all 1024px.
- `lib/fixtures/demo.json`: the full golden run (scores, hexes, advice, palette,
  measured API costs).
- Live YouCam APIs behind `/api/*` routes: skin analysis (7 concerns + masks),
  tone hexes, single-call full-face makeup VTO, garment VTO.

## Out of scope for this pass
Accounts, routine tracking over time, video/hair/accessories try-on,
multi-model panels, Shopify integration. Desktop is secondary — nail the phone
flow first.
